# Windows 实机验证清单

## 已完成的检查

- Python 语法检查通过。
- **42 项自动化用例通过**：19 项本地浏览器领取引擎测试，23 项时间/电源解析/任务XML/权限范围/监督机制测试。
- 浏览器用例拦截页面请求，不会调用真实领取服务；已查看生成的模拟页面截图。
- 生成的计划任务 XML 已通过微软官方 Task Scheduler XSD 校验；对校验发现的版本及触发器元素顺序问题已修正，并加入配置断言。
- 测试中 Windows 原生调用使用 mock 或纯数据输入，**不等于 Windows 实机验证**。

## 尚未执行：请在目标 Windows 电脑逐项确认

| 项目 | 操作 / 预期 | 风险说明 |
|---|---|---|
| 安装与依赖 | 普通本人桌面账号运行 `install.cmd`，生成 LocalAppData 运行目录与7个入口 | 公司策略可能禁止相关操作；不得绕过 |
| 特殊路径 | 源码目录/用户名含中文、空格时仍能运行入口 | 当前仅测试了字符串生成，尚未由 cmd.exe 实际解释 |
| 文件权限 | 检查运行根目录 ACL；会话与授权资料不可被普通其他用户读取 | 管理员/SYSTEM/同用户恶意程序不在此隔离保证内 |
| 手工登录 | 专用 Chrome 可见，登录成功后自动保存关闭 | 未登录时不要把空白页当成功 |
| 互斥锁 | 新安装尚待登录时，另开“仅检查”，应返回 `profile_busy` 而非第二个 Chrome | 不删除锁文件，不强杀日常 Chrome |
| 定位授权 | 本人同意后，程序只授权目标 origin；真实定位可用 | 不使用虚拟坐标或借用他人会话 |
| 只读检查 | `仅检查.cmd` 不领取、不主动定位，输出可解释状态 | `ready` 不代表领取资格已通过 |
| 任务配置 | “启用定时”后可见本人SID对应的任务，20:30、仅登录时、最低权限、不唤醒、不补跑 | 启用后到点可能真实领取，必须本人确认 |
| 隐藏执行 | 自动模式由 `pythonw.exe` 启动，无控制台或可见 Chrome | 当前尚未验证 Windows 是否有短暂窗口闪现 |
| 自然触发 | 等待一次真实20:30，核对 `run.log` 的 `mode=scheduled` 及网站结果 | 不用人工启动冒充定时触发成功 |
| 信息提醒 | 登录/定位失败时能看到原生信息框，约60秒自动结束 | 锁屏时可能错过；用户点“是”只打开人工处理入口 |
| 电源边界 | 经本人允许测试睡眠、休眠、Modern Standby、Fast Startup和唤醒 | 事件可读性/时间行为依系统而异，不擅自影响用户工作 |
| 超时清理 | 在专门测试环境模拟卡住的worker，确认只清理本次进程树 | 当前只验证清理调用，不保证原生进程回收已实测 |
| 停用与撤销 | 停用阻止后续定时；撤销定位同意阻止后续授予 | 已启动任务不强行中断，应等待退出 |

## 测试命令

以下在 Windows 源码目录的 PowerShell 中运行，先准备源码测试环境：

```powershell
uv venv .venv --python 3.13
uv pip install --python .venv/Scripts/python.exe -r requirements.txt
& ./.venv/Scripts/python.exe -m unittest discover -s tests -v
```

真实领取验证需要本人另外同意，一次任务最多5次，成功或出现阻断即停止；不要从代码手工调用私有接口、改定位结果或无限重试。
